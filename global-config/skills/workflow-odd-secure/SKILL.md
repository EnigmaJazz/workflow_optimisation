# Secure ODD route

Load after `workflow-route` selects authorized ODD work. Read [the secure ODD and native review contract](references/odd-and-review.md) before delegating, making a tracker, or starting review. The current `WORKFLOW.md` remains authoritative for task classification and delivery; this reference records the secure adaptation of the upstream protocol.

- PM closure order: apply `WORKFLOW.md` `Verification and advice budget by task type`. Run the required post-code check (an advisor, or `ce:review` where it substitutes) before the work-unit commit and resolve blockers. A true docs/metadata unit inside the actual-diff allowlist takes zero advisor and `gentle-ai-verify` Tasks; its PM factual/structural check and independent orchestrator readback replace them. The unit gets one initial writer plus ONE fresh correction across all pre-commit post-code gates: batch same-candidate findings, issue one consolidated brief, then targeted recheck. Install and commit the implementation first; only then run native risk assessment against the committed candidate. A pre-apply assessment is not required for an uninstalled sandbox result.
- Writer tier and finite matrix: `gentle-ai-worker-local` takes exactly ONE changed file per writer Task; cloud writers may batch a coherent multi-file unit. The six existing route classes keep the finite pre/post/verifier budget in `WORKFLOW.md`; do not add classes or unlimited refinement.

- Tiny-fix route: select the writer by dispatcher. An orchestrator's direct dispatch uses `general` (`openai/gpt-6-luna`); a PM dispatch uses `odd-apply` or `gentle-ai-worker` (DeepSeek family), never `general`, because the configured PMs run `openai/gpt-6.1-sol` (same OpenAI family). The model assignments are in `global-config/opencode.json`: `general` line 243, `pm-odd`/`pm-systematic` lines 2065/2198, `odd-apply`/`gentle-ai-worker` lines 2340/369. No writer may share its dispatcher's model family. For understood, mechanically bounded few-line work with no contract/security effect, create no tracker, advice record, or mirror on the orchestrator route. It is passive-only; any medium/high assessment automatically escalates out. Its one-way tripwire is escalation-only and the named constants in `global-config/plugins/systematic-routing-guard.ts` are authoritative; changed-line count never selects a route. The PM verifies the in-project traces only: the `ROUTER-LOG.md` row carrying commit and changed lines, written by that same writer within its authorized paths (which MUST include `ROUTER-LOG.md`), and, for a mid-unit fix, the tracker `## Log` entry as part of the sanctioned tracker update. The permit-consumption log line is the guard's own diagnostic record, observed by whoever audits the guard log; it is not a PM obligation, and its absence MUST NOT block a unit. Tiny-fix briefs' `allowed_paths` MUST include `ROUTER-LOG.md`. For a PM tiny fix, include the required tracker `## Log` entry as part of the sanctioned tracker update; acceptance criteria must not forbid that line. The PM obtains the native risk assessment and any review evidence through its own HOST review tools; the sandbox writer is never asked to produce review evidence and never enters the review path. A writer brief MUST NOT require review evidence, and a writer's inability to produce it MUST NOT block the unit. Temporary writer deviation (owner decision, 2026-10-17) is superseded; the dispatcher-specific assignment above is authoritative. Tiny fixes ARE COMMITTED: the PM commits the applied implementation, then commits applicable metadata in a separate metadata work unit before returning DONE; the orchestrator commits after the writer's applied result. Tiny-fix briefs MUST permit the applicable commit, never forbid it. Fill the `ROUTER-LOG.md` commit field at closure; `PENDING-COMMIT` is expected mid-unit.

- Temporary writer deviation (owner decision, 2026-10-17) is superseded: the dispatcher-specific tiny-fix assignments above replace the old blanket `general` rule; this note does not authorize a same-family PM writer.
- The orchestrator and PMs are coordinators, not sandbox workers. For an ODD unit, dispatch `odd-apply` as the implementation writer; it owns only the ODD route and does not replace `systematic-implementer`. Project writes, executions and checks use the authorized sandbox worker; the worker does not commit, and the PM commits its applied result through the reviewed fixed `host_git_commit` operation. The upstream inline-edit route maps to a sandbox worker even for one file.

- When the two-file writer (two or more non-trivial files), preparation, or long-session trigger fires, delegate its bounded task. Use the evidence budget instead of file counts: one parallel batch (at most 3 tool/read calls, about 10k tokens); beyond that or more than about 5 sequential lookups goes to one read-only explorer returning at most about 2k tokens with `path:line`. For substantial work record the per-task route and trigger evidence before implementation; persist Task result and actual checks afterward in the tracker and complete Magic Context mirror.
- Keep RDD separate and user-owned. In v3.5 an unset switch resolves on; read effective mode and deciding source per project before review and never toggle it automatically. Use native scoped provider-returned review operations; do not synthesize receipts or replay isolated reviewer prompts. A disabled RDD mode does not prevent ordinary functional checks.
- Before any commit that may become an RDD candidate, require the delegated worker's staged reviewability receipt and enforce the local per-commit line/byte cap from the reference. Native Gentle AI START remains the final 200 KiB serialized-input authority; budget stops are split/abandon signals, never invitations to bypass the guard.
- Confirm real Task dispatch and result, project permissions, exact test runner, relevant Systematic specialist, and applicable review before closing.
