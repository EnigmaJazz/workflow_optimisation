# Q77 — Pre-code advice record

## advisor-integration-pre (2026-10-17)

- **BLOCKER — the contract must change before prompt work.** `docs/specs/pm-handoff.md:7` defines the input brief schema without the mirror-readback hashes, while `docs/specs/pm-handoff.md:117` makes complete mirror readback a PM prerequisite for `DONE`. Leaving those clauses unchanged would make the orchestrator violate its own schema and leave the PM obligated to perform a read it cannot perform.
- **BLOCKER — clarify the result envelope.** `docs/specs/pm-handoff.md:96-99` has `readback.magic_context_reference` describing an exact key/item and complete-body readback result. Because the PM cannot read the body, this field must be extended or re-described to record the hash comparison and its method, not falsely claim a PM-performed body read.
- **Ownership constraint.** `docs/specs/pm-handoff.md:113` assigns the complete Magic Context mirror write to the metadata worker. Keep that ownership unchanged; the orchestrator's read is being re-routed, not the mirror write.
- **Integrity risk / independent check.** Supplying the tracker body in the orchestrator's brief could mask tracker/mirror divergence. Instead, the orchestrator supplies `tracker_sha256` and `mirror_sha256`; the PM independently hashes the committed tracker FILE itself and compares its result with the supplied `tracker_sha256`. Do not have the orchestrator supply both sides of the PM comparison, since one failure could make two supplied values agree while both diverge from the canonical tracker.
- **Size hazard.** `docs/specs/pm-handoff.md:11` caps PM prompts at approximately 6,000 characters, while the brief has no documented size cap at `docs/specs/pm-handoff.md:7`. A 20–30 KB tracker body in a brief creates a material token-budget risk. This is a primary reason to prefer the two 64-character hashes over a body.
- **Withdrawn recommendation / owner correction.** The initial recommendation to register `ctx_memory` for subagents is WITHDRAWN. OWNER CORRECTION: Magic Context 0.46 removed `ctx_memory` from subagents BY DESIGN. Registering it would fight the plugin's deliberate intent and is not to be pursued. This is not a broker or runtime gap; the orchestrator retains the memory read capability.
- **Recommended decomposition.** U1: amend the spec (brief fields, PM obligation, result envelope) and add a schema test. U2: update the orchestrator overlay, both PM prompts, and regeneration chain. U3: runtime diagnosis is now CLOSED by the owner-confirmed tool-registration evidence; the behavior falsifier remains a future HOST-ONLY smoke test, not a repo-testable claim.
